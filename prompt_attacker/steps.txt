RUN_ORCHESTRATOR.PY - PRAKTICKY NAVOD PRO ODEVZDANI A TESTOVANI

Tento projekt se ma ovladat hlavne pres:

    python3 run_orchestrator.py --config config_orchestrator.yaml <akce>

Hlavni soubor:

    prompt_attacker/run_orchestrator.py

Hlavni testovaci dataset pro oponenta:

    prompt_attacker/dataset/oponent_show/

Tento dataset obsahuje hotove JSON prompty pro jednotlive utocne metody. Kazdy
soubor je list objektu ve stylu:

    {
      "id": ...,
      "original_prompt": "...",
      "prompt": "...",
      "response": "..."
    }

Pro `--attack-batch`, `--attack-single`, `--defense` a defaultne i
`--defense-apply-rules` se bere vstup z klice `dataset_to_attack_path`,
aktualne:

    /storage/brno2/home/xkaska01/master/prompt_attacker/dataset/oponent_show

Vystupy a joby jdou do `results_dir`, aktualne:

    /storage/brno2/home/xkaska01/master/prompt_attacker/results/oponent_show


1. Priprava prostredi

Typicky pred spustenim na Metacentru:

    module add mambaforge
    mamba activate /storage/brno2/home/xkaska01/.conda/envs/diplomka
    cd /storage/brno2/home/xkaska01/master/prompt_attacker
    export CUDA_VISIBLE_DEVICES=0

Pro interaktivni ladeni na GPU:

    qsub -I -l walltime=8:0:0 -q default@pbs-m1.metacentrum.cz -l select=1:ncpus=1:ngpus=1:mem=200gb:gpu_mem=60gb:scratch_local=400gb

Pokud pouzivas `use_ollama: true`, musi byt dostupna Ollama a modely. Job
templates umi u nekterych jobu spustit Ollamu automaticky, ale pri rucnim
interactive behu si dostupnost Ollamy over.


2. Konfigurace

Hlavni konfigurace:

    config_orchestrator.yaml

Dulezite klice:

    local_model_path / victim_llm
        Cesta k lokalnim modelum nebo model path pro vLLM.

    models_dir
        Slozka, ze ktere se automaticky nactou modely pro batch rezimy.
        Typicky stejna cesta jako `local_model_path`, tedy `models/`.

    results_dir
        Kam se ukladaji vysledky a generovane job skripty.

    dataset_to_attack_path
        Slozka s JSON soubory pro `--attack-batch`, `--attack-single`,
        `--defense`. Pro testovani odevzdani pouzivej `dataset/oponent_show`.

    dataset_to_train_attack_path
        Legacy dataset pro stare generovani attack JSONu z puvodniho CSV
        workflow. Aktualni attack/defense workflow pouziva hotove JSONy z
        `dataset_to_attack_path`.

    use_ollama
        true  = vola se Ollama model podle nazvu, napr. `gemma3:12b`.
        false = pouziva se lokalni model pres vLLM/HuggingFace cestu.
        Pro `false` musi beh bezet na GPU uzlu s dostupnym CUDA driverem
        (`libcuda.so.1`). Na login uzlu interactive vLLM spadne.

    dry_run
        true  = job skripty se pouze vytvori, ale neposlou se pres `qsub`.
        false = job skripty se vytvori a rovnou se poslou pres `qsub`.

    interactive_heartbeat_seconds
        Po kolika sekundach ma interactive rezim vypsat, ze proces porad bezi.
        Napr. `30`; hodnota `0` heartbeat vypne.

    vllm_use_v1
        false = orchestrator nastavi `VLLM_USE_V1=0`. To je uzitecny fallback
        na HPC uzlech, kde vLLM V1 engine pada na CUDA kernelech.
        Pokud vis, ze aktualni GPU a instalace vLLM V1 podporuji, muzes dat
        `true`.

    normalize_cuda_visible_devices
        true = pokud scheduler nastavi `CUDA_VISIBLE_DEVICES` jako GPU UUID
        (`GPU-...`), interactive vLLM beh ho prepise na ciselnou hodnotu `0`.
        To obchazi vLLM chybu, kde se UUID pokousi parsovat jako integer.

    target_model
        Jeden model pro `--attack-single` a defaultni beh.
        Pri `use_ollama: false` se tento nazev automaticky mapuje na lokalni
        slozku `models_dir/<target_model>`, napr.
        `models/gemma3:12b`.

    single_attack
        Jeden konkretni attack JSON pro `--attack-single`, napr. `_1_cypher`.
        Hodnota `null` znamena vsechny JSON utoky v `dataset_to_attack_path`.

Batch rezimy uz nepouzivaji `target_models` ani `ollama_models`. Modely se berou
automaticky z adresaru `models_dir`, kde musi existovat jako slozky, napr.:

    models/gemma3:12b
    models/falcon3:7b
    models/qwen2.5:14b

    defense_train_*
        Parametry pro trenovani stromove obrany v `defense/def.py`.
        Nejdalsi jsou:

            defense_train_dataset
            defense_train_output_rule
            defense_train_log_dir
            defense_train_use_vllm
            defense_train_vllm_model
            defense_train_gen_model
            defense_train_judge_model
            defense_train_pop_size
            defense_train_n_gen
            defense_train_n_tries
            defense_train_max_examples

    defense_apply_*
        Parametry pro aplikovani natrenovane rule-tree obrany pres
        `defense/apply_rules.py`:

            defense_apply_input_dir
            defense_apply_output_dir
            defense_apply_rule_path
            defense_apply_seed

    defense_vocab_*
        Parametry pro vytvoreni slovniku tokenizeru pres
        `defense/create_vocabulary.py`.

Pro bezpecny test pred odevzdanim doporucuji docasne:

    dry_run: true
    target_model: "gemma3:12b"
    single_attack: "_1_cypher"


3. Obecne chovani run_orchestrator.py

Zakladni tvar:

    python3 run_orchestrator.py --config config_orchestrator.yaml <akce>

Bez `--interactive`:

    - vytvori PBS job skripty do `results_dir/jobs/` nebo jine cilove slozky;
    - pokud `dry_run: false`, rovnou vola `qsub`;
    - pokud `dry_run: true`, joby jen pripravi.

S `--interactive`:

    - nespousti PBS job;
    - vola cilovy Python skript hned v aktualnim terminalu;
    - pred kazdym krokem vypise model/vstup, prikaz a start;
    - behem dlouhych kroku vypisuje heartbeat podle
      `interactive_heartbeat_seconds`;
    - po dokonceni vypise celkovy cas nebo exit code chyby;
    - hodi se na ladeni maleho datasetu nebo jednoho modelu.
    - pri `use_ollama: false` musi byt terminal uz uvnitr GPU alokace
      z `qsub -I`; orchestrator to pred startem zkontroluje.


4. Prehled vsech akci

4.1 Help

    python3 run_orchestrator.py --help

Ukaze dostupne argumenty. Aktualni kod pouziva flagy, ne subcommandy. Tedy
spravne je napr. `--attack-batch`, ne `attack --mode batch`.


4.2 Attack batch nad oponent_show datasetem

    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-batch

Co to dela:

    - vezme vsechny `.json` soubory z `dataset_to_attack_path`;
    - pro kazdy modelovy adresar v `models_dir` vytvori job;
    - kazdy job vola:

        python3 scripts/only_attack_batch.py <local_model_path> <input_json> <out_dir> <use_ollama> <target_model>

    - vstupem je napr. `dataset/oponent_show/_1_cypher.json`;
    - vystupem je JSON se stejnym nazvem v `results_dir/<model>/`;
    - pokud `results_dir` obsahuje `{model}`, pouzije se tato sablona misto
      automaticke podslozky.

Pouziti pro test bez odeslani jobu:

    # v configu nastav dry_run: true
    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-batch

Pouziti pro prime spusteni v terminalu:

    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-batch --interactive

Pozor:

    - pri `--interactive` se spusti vsechny modely ze slozky `models_dir` za
      sebou, coz muze trvat dlouho;
    - modelovy set upravis fyzicky ve slozce `models_dir`.


4.3 Attack single nad oponent_show datasetem

    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-single

Co to dela:

    - vezme jeden `.json` soubor podle `single_attack`;
    - pokud `single_attack: null`, vezme vsechny `.json` soubory;
    - pouzije pouze jeden model z `target_model`;
    - vytvori joby volajici:

        python3 scripts/only_attack.py <local_model_path> <input_json> <out_dir> <use_ollama> <target_model>

    - vystupy ulozi do `results_dir`.

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-single --interactive

Vyber konkretniho utoku bez upravy configu:

    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-single --single-attack _1_cypher

Vypsani dostupnych utoku:

    python3 run_orchestrator.py --config config_orchestrator.yaml --list-attacks

Rozdil proti `--attack-batch`:

    - `--attack-single` pouziva jen `target_model`;
    - `--attack-batch` iteruje pres modelove slozky v `models_dir`;
    - `only_attack_batch.py` umi davkovat volani, `only_attack.py` jede jednoduseji.


4.4 Defense nad oponent_show datasetem

Podporovane obrany:

    rallm
    llamaguard
    safeguard
    ea

Priklad:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense ea

Co to dela:

    - vezme vsechny `.json` soubory z `dataset_to_attack_path`;
    - pro kazdy modelovy adresar v `models_dir` vytvori job;
    - kazdy job vola:

        python3 scripts/only_defense_batch.py --per-victim <local_model> --defense <typ> --model <target_model> --input <json> --out_dir <dir> --use-ollama <true|false>

    - vystupem je JSON se stejnym nazvem v `results_dir/<model>/`;
    - do kazde polozky prida `"defense": "<typ>"`.

Priklady:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense rallm
    python3 run_orchestrator.py --config config_orchestrator.yaml --defense llamaguard
    python3 run_orchestrator.py --config config_orchestrator.yaml --defense safeguard
    python3 run_orchestrator.py --config config_orchestrator.yaml --defense ea

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense ea --interactive

Pozor:

    - `ea` je lehka lokalni prompt-rewrite obrana z `defense/defense_EA.py`;
    - `rallm`, `llamaguard`, `safeguard` bali LLM a volaji `response_batch`;
    - pri `use_ollama: true` musi byt model dostupny v Ollame.


4.4.1 Trenovani vlastni rule-tree obrany

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-train

Co to dela:

    - vytvori job pro `defense/def.py`;
    - dataset bere z `defense_train_dataset`;
    - vystupni pravidlo ulozi do `defense_train_output_rule`;
    - logy uklada do `defense_train_log_dir`;
    - parametry evoluce bere z `defense_train_pop_size`,
      `defense_train_n_gen`, `defense_train_n_tries`,
      `defense_train_max_examples`;
    - modely bere z `defense_train_vllm_model`,
      `defense_train_gen_model`, `defense_train_judge_model`.

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-train --interactive

Rychly sanity test:

    defense_train_pop_size: 2
    defense_train_n_gen: 1
    defense_train_n_tries: 1
    defense_train_max_examples: 2

Pozor:

    - trenovani muze byt velmi drahe, proto pred ostrym behem zmensi parametry;
    - pokud `defense_train_use_vllm: true`, musi sedet lokalni cesta
      `defense_train_vllm_model`;
    - judge model se vola pres Ollamu podle `defense_train_judge_model`.


4.4.2 Aplikovani natrenovane obrany na dataset

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-apply-rules

Co to dela:

    - vola `defense/apply_rules.py`;
    - vezme vsechny `.json` soubory z `defense_apply_input_dir`;
    - nacte pravidlo z `defense_apply_rule_path`;
    - upravene JSONy ulozi do `defense_apply_output_dir`;
    - zachova strukturu polozek, jen prepise hodnotu `prompt`.

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-apply-rules --interactive


4.4.3 Trenovani a aplikovani v jednom jobu

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-train-apply

Co to dela:

    - nejdriv spusti `--defense-train`;
    - potom pouzije vznikle `defense_train_output_rule` jako
      `defense_apply_rule_path`;
    - hodi se, kdyz chces mit jeden PBS job pro cely workflow obrany.


4.4.4 Vytvoreni vocabulary souboru pro obranu

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-create-vocab

Co to dela:

    - vola `defense/create_vocabulary.py`;
    - tokenizer/model cte z `defense_vocab_model_dir`;
    - vystup ulozi do `defense_vocab_output_file`.

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-create-vocab --interactive


4.5 Evaluate

    python3 run_orchestrator.py --config config_orchestrator.yaml --evaluate

Co to dela:

    - pro kazdy modelovy adresar v `models_dir` vytvori eval job;
    - job vola:

        python3 evaluate/evaluate_full_results_datasets.py <model> DEFENSE_SAFEGUARD

    - vystup jobu se uklada do:

        results_dir/benign/stats/SAFEGUARD/job_<model>.sh

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --evaluate --interactive

Pozor:

    - evaluacni skript ma uvnitr hardcodovane cesty `BASE_INPUT_DIR` a
      `BASE_OUTPUT_DIR`;
    - judge model je hardcodovany jako `gemma3:12b`;
    - obrana je v orchestratoru hardcodovana jako `DEFENSE_SAFEGUARD`;
    - pred odevzdanim je dobre overit, ze tyto cesty odpovidaji aktualnim
      vysledkum, jinak evaluate nenajde vstupy.


4.6 Defaultni beh bez akce

    python3 run_orchestrator.py --config config_orchestrator.yaml

Co to dela:

    - pouzije stejnou JSON cestu jako `--attack-single`;
    - vybere JSON soubor podle `single_attack`;
    - pokud `single_attack: null`, vybere vsechny `.json` soubory;
    - vola:

        python3 scripts/only_attack.py <local_model_path> <input_json> <results_dir> <use_ollama> <target_model>

    - vstupem je napr. `dataset/oponent_show/_1_cypher.json`;
    - pouzije jeden `target_model`, ne cely `models_dir`.

Pozor:

    - puvodni module-run rezim pres `ATTACK_MODULES` cetl CSV pres
      `dataset_to_train_attack_path`;
    - pokud nekdy budes chtit znovu generovat attack JSONy z CSV, je potreba
      spoustet konkretni generator mimo tento defaultni JSON beh.

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --interactive


4.7 Run pipeline

    python3 run_orchestrator.py --config config_orchestrator.yaml --run-pipeline

Co ma delat podle kodu:

    - vytvori docasny `config_pipeline_temp.yaml`;
    - jako dataset pouzije `dataset_to_attack_path`, pokud existuje, jinak
      `dataset_to_train_attack_path`;
    - vytvori job, ktery vola:

        python3 scripts/run_pipeline.py --config_file config_pipeline_temp.yaml

S vlastnim vystupem:

    python3 run_orchestrator.py --config config_orchestrator.yaml --run-pipeline --pipeline-out results/my_pipeline_out

Prime spusteni:

    python3 run_orchestrator.py --config config_orchestrator.yaml --run-pipeline --interactive

Pozor:

    - v aktualnim repozitari `scripts/run_pipeline.py` neexistuje;
    - tento rezim je tedy ted rozbity, dokud se `run_pipeline.py` nedoplni nebo
      se `--run-pipeline` neupravi.


5. Doporuceny testovaci postup pro oponent_show

5.1 Otestovat generovani jobu bez qsub

V `config_orchestrator.yaml` docasne nastav:

    dry_run: true
    target_model: "gemma3:12b"
    single_attack: "_1_cypher"

Pak:

    cd /storage/brno2/home/xkaska01/master/prompt_attacker
    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-batch

Ocekavani:

    - vytvori se joby v `results/oponent_show/<model>/jobs/`;
    - nic se neodesle pres `qsub`;
    - pro kazdy JSON v `dataset/oponent_show` vznikne jeden job pro kazdy
      modelovy adresar ve `models_dir`.


5.2 Otestovat jeden job rucne

Vyber jeden vytvoreny job:

    bash results/oponent_show/gemma3:12b/jobs/job_onlyattackbatch__1_cypher.sh

Ocekavani:

    - job zavola `scripts/only_attack_batch.py`;
    - vytvori vystup napr. `results/oponent_show/gemma3:12b/_1_cypher.json`.


5.3 Otestovat interactive rezim

Pouze pro maly pocet modelu:

    python3 run_orchestrator.py --config config_orchestrator.yaml --attack-batch --interactive

Ocekavani:

    - skripty se nespousti pres PBS;
    - bezi primo v terminalu;
    - orchestrator prubezne vypisuje aktualni model, vstupni JSON,
      spousteny prikaz a heartbeat;
    - pri `use_ollama: false` orchestrator vypise i dulezite vLLM env hodnoty
      jako `VLLM_USE_V1=0` nebo `CUDA_VISIBLE_DEVICES=0`, pokud je nastavuje;
    - pri velkem poctu modelu to bude dlouhe.


5.4 Otestovat defense

Nejrychlejsi zacatek pro lightweight EA wrapper:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense ea

Nebo interaktivne:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense ea --interactive

Test vlastni rule-tree obrany bez velkeho behu:

    # v configu nastav male hodnoty:
    # defense_train_pop_size: 2
    # defense_train_n_gen: 1
    # defense_train_n_tries: 1
    # defense_train_max_examples: 2
    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-train

Po natrenovani pravidla:

    python3 run_orchestrator.py --config config_orchestrator.yaml --defense-apply-rules
